API для замовлень клієнтів

API дозволяє вашій CRM, інтернет-магазину чи обліковій системі автоматично передавати в Еко­вент B2B замовлення ваших клієнтів — без ручного введення в кабінеті. Замовлення, створені через API, проходять ті самі перевірки, ліміти й сповіщення, що й створені в кабінеті, і видно їх у кабінеті у вкладці «Замовлення клієнтів».

Що вміє API

  • віддавати каталог з вашими цінами (ціна партнера й РРЦ) — щоб зіставити товари з вашими;
  • показувати закупівлі із залишками, з яких можна відправляти клієнтам;
  • створювати, змінювати й скасовувати замовлення клієнтів;
  • додавати маркування (етикетку ТТН Нової пошти) та ваші документи до замовлення;
  • віддавати статус замовлення, зокрема статус і № у LP-CRM після передачі в роботу, і список змінених замовлень для синхронізації.
Базова адреса: https://ecovent-nakladni.pages.dev/api/v1. Формат — JSON (UTF-8), гроші — гривні з копійками (число), час — ISO 8601 в UTC (2026-11-06T18:19:17.534Z).

Ключ і вхід

Ключ створює керівник вашої команди в кабінеті партнера: Налаштування → API для замовлень → + Ключ (або ваш менеджер Еко­вент). Ключ має вигляд ecv_ + 48 символів і показується лише один раз. Зберігайте його на сервері, не в коді сайту чи мобільного застосунку.

Передавайте ключ у кожному запиті одним із заголовків:

Authorization: Bearer ecv_ваш_ключ
# або
X-Api-Key: ecv_ваш_ключ

Ключ діє від імені вашої команди з правами керівника. Можна мати до 5 активних ключів (наприклад, окремо для сайту й для CRM). У кабінеті видно, коли кожен ключ використовувався востаннє; відкликаний ключ перестає працювати одразу. Про створення ключа приходить повідомлення в Telegram.

Якщо ключ міг потрапити до сторонніх — відкличте його в кабінеті й створіть новий.

Типовий сценарій

  1. Зіставте товари. Раз на день (або при зміні цін) запитуйте GET /products і зберігайте product_id та article. У замовленні товар можна вказати будь-яким із них.
  2. Створіть замовлення. POST /orders з ПІБ і телефоном клієнта, товарами й вашим номером замовлення в external_id. Повтор того ж запиту не створить дубль.
  3. Додайте маркування. Створіть ТТН у своєму кабінеті Нової пошти й надішліть PDF етикетки: POST /orders/{id}/files. Без маркування замовлення не передадуть у роботу (missing_docs покаже, чого бракує).
  4. Стежте за статусом. Кожні 5–15 хвилин запитуйте GET /orders?updated_since=… — отримаєте лише змінені замовлення: передані в роботу, з новим статусом у LP-CRM, скасовані.

Загальні правила

ЩоПравило
Клієнтname — обов’язково (до 150 символів); phone — український номер: 0XXXXXXXXX або 380XXXXXXXXX (пробіли, дужки, «+» можна — вони відкидаються).
ТовариЛише з вашого каталогу (бренди, відкриті вашій команді). qty — ціле число 1–999. Ціна — ваша ціна партнера на момент замовлення (її не передають — рахує система).
Звідки товарБез supply_id — «без закупівлі»: товар іде в найновішу чернетку закупівлі з доставкою клієнтам, а якщо її немає — у відкриту закупівлю (у межах лімітів вашої команди). З supply_id — з конкретної закупівлі; кількість не більша за залишок (GET /supplies).
ЛімітиЛіміт відкритої закупівлі й ліміт неоплачених закупівель — як у кабінеті. Перевищення — помилка 400 з поясненням.
ТТННеобов’язково; 6–40 цифр / латинських літер. Одна ТТН — лише в одному замовленні.
ЗміниЗмінити чи скасувати можна, доки status = "new". Після передачі в роботу — лише через вашого менеджера.
ФайлиPDF або зображення до 5 МБ, до 15 файлів у замовленні. Те саме маркування двічі не приймається.
ЧастотаРозумне навантаження: до ~60 запитів за хвилину. Синхронізацію статусів — не частіше ніж раз на 5 хвилин.

Види ваших документів

GET/api/v1/doc-types

Документи, які ваша команда налаштувала в кабінеті (чек, гарантійний талон…). required: true — без нього замовлення не передадуть у роботу.

Отримати замовлення

GET/api/v1/orders/{id}

{id} — число (2051) або номер (B2B-2051). Відповідь — об’єкт замовлення з файлами й missing_docs. За вашим номером: GET /api/v1/orders?external_id=SHOP-1001.

Змінити замовлення

PUT/api/v1/orders/{id}

Лише поки status = "new" і pending_changes = false. Тіло — як при створенні, повністю (клієнт, товари, ТТН, коментар): передане замінює попереднє. Відповідь: { "order": { … } }.

Скасувати замовлення

POST/api/v1/orders/{id}/cancel

Лише поки status = "new". Товари замовлення повертаються в закупівлю (або прибираються з чернетки). Відповідь: { "order": { …, "status": "cancelled" } }.

ПолеОпис

Відповідь 201: { "file_id": 77, "warnings": [], "order": { … } }. У warnings — зауваження до маркування (наприклад, ТТН на етикетці не збігається з ТТН замовлення). Те саме маркування вдруге — 409.

Прибрати файл

DELETE/api/v1/orders/{id}/files/{file_id}

Поки status = "new". Відповідь: { "order": { … } }.

Синхронізація статусів

Зберігайте у себе next_updated_since з останньої відповіді й передавайте його наступного разу:

GET /api/v1/orders?updated_since=2026-11-06T18:40:02.120Z&limit=200
→ оновіть у себе кожне замовлення з "orders" (за "id" або "external_id")
→ якщо "has_more": true — одразу запитайте ще раз із новим next_updated_since

Замовлення потрапляє в цей список, коли змінюється його склад чи дані, статус (передано в роботу, скасовано) або статус / № у LP-CRM. Статуси LP-CRM оновлюються в нас приблизно раз на 30 хвилин.

  curl_setopt_array($ch, [

}

Питання

Що бачить наш менеджер у кабінеті?

Те саме замовлення, що й створене вручну. В історії замовлення автором буде «API · назва ключа». Про нове замовлення приходять ті самі сповіщення в Telegram.

Чи можна передати ціну продажу клієнту?

Ні — у замовленні рахується ваша ціна партнера за каталогом. Ціну для клієнта ви ведете у своїй системі.

Чи можна створювати закупівлі через API?

Поки що ні: API v1 — для замовлень клієнтів. Закупівлі оформлюються в кабінеті.

Як протестувати?

Створіть замовлення з коментарем «ТЕСТ» і одразу скасуйте його (POST /orders/{id}/cancel) — скасоване замовлення в роботу не піде. Або попросіть менеджера про окремий тестовий кабінет.

Куди звертатися?

До вашого менеджера Еко­вент — він бачить усі запити ваших ключів у кабінеті.
